# Function-Agent 系统架构文档

## 1. 项目概述

Function-Agent 是一个 AI 驱动的高等数学智能助手，通过自然语言对话结合可视化图形组件帮助用户理解抽象数学概念。纯前端架构，无需后端服务，数据存储于浏览器 localStorage。

### 技术栈

| 类别 | 技术 |
|------|------|
| 运行时 | 原生 HTML5 + CSS3 + JavaScript (ES Modules) |
| 构建工具 | 无（零构建、零打包） |
| 公式渲染 | KaTeX 0.16.11（本地 `lib/`） |
| 图表引擎 | Plotly.js 2.35.0（2D/3D 图表）+ Canvas 2D（动画），本地 `lib/` |
| 数学计算 | math.js 13.2.2，本地 `lib/` |
| Markdown | marked.js 12.0.2，本地 `lib/` |
| 代码高亮 | highlight.js 11.9.0，本地 `lib/` |
| 字体 | Noto Sans SC、JetBrains Mono 等（本地 `lib/fonts/`） |
| AI 通信 | OpenAI Function Calling 兼容 API（SSE 流式） |

> 所有外部依赖库均已本地化存放在 `lib/` 目录，支持完全离线使用，无需 CDN。

## 3. 分层架构

### 3.1 状态层（stores/）

基于发布-订阅模式的响应式状态管理，不依赖任何外部框架。

| Store | 职责 | 持久化 |
|-------|------|--------|
| `ChatStore` | 会话列表、活动会话、消息增删改查 | localStorage（防抖 500ms） |
| `SettingsStore` | 用户设置（API 配置、Prompt 分段、命名偏好、主题等） | localStorage（实时） |
| `ToolStore` | 工具调用执行状态（执行中/成功/失败） | 不持久化 |
| `LearningStatsStore` | Token 用量、工具使用次数、按数学分支分类统计 | localStorage |

**Store 基类**（`store-base.js`）提供：
- `getState()` — 获取当前状态浅拷贝
- `setState(partial)` — 合并更新并通知监听器
- `subscribe(key, callback)` — 订阅特定 key 的变化
- `subscribeAll(callback)` — 订阅所有状态变化

### 3.2 服务层（services/）

| 模块 | 职责 |
|------|------|
| `ai-client.js` | AI 流式 SSE 请求（`createStream`）、图片识别（`analyzeImages`）、收藏/会话 AI 标题生成（`generateFavoriteTitle`） |
| `stream-parser.js` | SSE 数据块解析，提取文本增量与工具调用 |
| `math-evaluator.js` | 数学表达式安全求值（基于 math.js） |
| `storage-adapter.js` | localStorage 读写封装，含容量检测 |

### 3.3 Prompt 管理（prompt.js）⬅ 新增模块

将 System Prompt 拆分为四个语义独立的部分，支持设置页分段编辑：

```
prompt.js
├── DEFAULT_ROLE_DEFINITION     # 角色定义
├── DEFAULT_TOOLS_LIST          # 可用工具列表
├── DEFAULT_GUIDELINES          # 注意事项
├── DEFAULT_SUPPLEMENT          # 其他补充
├── DEFAULT_VISION_SYSTEM_PROMPT # 图片识别提示词
└── buildSystemPrompt(parts)    # 拼合函数
```

每个部分可在设置页独立编辑，保存后通过 `buildSystemPrompt()` 自动合并为完整的 System Prompt 发送给 LLM。

### 3.4 工具链层（tools/）

核心设计：**四段式解耦架构**

```
Schema → Definition → Registry → Executor
  |           |           |          |
  v           v           v          v
参数定义   执行逻辑    注册中心    调用分发
```

1. **Schema**（`schemas.js`）：29 个 OpenAI Function Calling 格式的 JSON Schema
2. **Definition**（`definitions/*.js`）：29 个执行器，各自实现具体的数学计算或数据生成逻辑
3. **Registry**（`registry.js`）：`Map<name, {schema, executor}>` 工具注册表单例
4. **Executor**（`executor.js`）：从 registry 查找执行器，解析参数后分发执行
5. **Register-all**（`register-all.js`）：导入所有 definition 并调用 `registry.register(schema, executor)`

### 3.5 组件层（components/）

| 模块 | 职责 |
|------|------|
| `chat-area.js` | **核心枢纽**：消息发送、Agent Loop 驱动、流式响应处理 |

## 4. Agent Loop 架构

这是整个应用的核心运行机制，位于 `chat-area.js` 的 `runAI` 函数中。

```
用户输入 → handleSend()
              |
              ├─ 图片处理（可选）：analyzeImages() → 组合内容
              ├─ 添加用户消息
              ├─ 创建助手占位消息
              └─ 启动 runAI()
                    |
                    └─ while(true) ← Agent Loop
                         |
                         ├─ buildMessages()：构建 API 消息序列
                         │    ├─ 过滤占位消息 / 错误消息 / thinking 消息
                         │    ├─ stripThinkContent()：剥离思维链标签
                         │    ├─ 工具结果转自然语言
                         │    └─ compactMessages()：角色交替合规化
                         |
                         ├─ createStream()：SSE 请求
                         │    ├─ 实时流式输出文本 → onContentDelta
                         │    └─ 返回 { toolCalls | null }
                         |
                         ├─ 无 toolCalls → Loop 结束
                         │    └─ _autoTitle()：自动生成会话标题
                         |
                         └─ 有 toolCalls → 执行工具
                              ├─ 逐个 executeToolCall()
                              │    ├─ registry.getExecutor(name)
                              │    └─ executor(args) → { status, componentType, props }
                              ├─ 追加 tool 消息
                              ├─ 创建新的助手占位消息
                              └─ depth++ → 继续下一轮 while
```

### 4.1 并发控制机制

| 机制 | 说明 |
|------|------|
| **发送锁**（`_sendLock`） | `handleSend` 级别的串行锁，在 finally 中复位 |
| **代际守卫**（`_runAIGeneration`） | 每次 `runAI` 启动递增，finally 中比对代际 ID 防止旧实例覆盖新状态 |
| **活跃流计数**（`_activeStreams`） | 双重保险，`runAI` 开始 +1、finally -1 |
| **AbortController** | 停止按钮发出 abort 信号，`createStream` 响应 `signal` |
| **深度限制**（`MAX_TOOL_DEPTH=25`） | 防止工具无限调用 |

### 4.2 isStreaming 复位规则

`isStreaming` 状态的复位权**独占**于 `runAI` 的 `finally` 块，由代际守卫保护。其他任何模块（包括 stopBtn、createStream）绝不直接修改此状态。

## 5. 数据流

### 5.1 消息模型

```
Message {
  id: string              // UUID
  role: 'user' | 'assistant' | 'tool'
  content: string | null   // 消息文本
  images?: string[]       // 用户消息的图片 base64（仅 role=user）
  toolCalls?: ToolCall[]   // 助手消息的工具调用（仅 role=assistant）
  toolCallId?: string      // 工具结果关联的调用 ID（仅 role=tool）
  toolResult?: Object      // 工具执行结果（仅 role=tool）
  isStreaming?: boolean     // 是否正在流式输出
  _isLocalError?: boolean   // 客户端生成的错误消息（不发送给 API）
  _isVisionThinking?: boolean // 图片识别中占位（不发送给 API）
  createdAt: string         // ISO 时间戳
}

ToolCall {
  id: string
  type: 'function'
  function: {
    name: string
    arguments: string  // JSON 字符串
  }
}
```

### 5.2 持久化模型

```
Session {
  id: string
  title: string
  createdAt: string
  updatedAt: string
  messages: Message[]
}
```

localStorage 键值：

| 键 | 内容 | 说明 |
|----|------|------|
| `gaoshu_sessions` | `Session[]` | 所有会话（含消息） |
| `gaoshu_active_session_id` | `string \| null` | 当前活动会话 ID |
| `gaoshu_settings` | `Settings` | 用户设置（含 Prompt 分段） |
| `gaoshu_theme` | `string` | 主题设置 |
| `gaoshu_favorites` | `FavoriteItem[]` | 收藏数据 |
| `gaoshu_learning_stats` | `LearningStats` | 学习统计数据 |

## 6. 工具注册与渲染管线

```
                        注册时（app.js 启动）
                              |
                    registerAllTools()
                              |
              definitions/*.js executor  ──→ registry.register(schema, executor)
              schemas.js schema           ──→
                              |
                    ┌─────────────────────┐
                    |     registry Map     |
                    | name → {schema,     |
                    |        executor}     |
                    └──────────┬──────────┘
                               |
              ┌────────────────┼────────────────┐
              |                |                |
      getAllSchemas()    getExecutor()     has()
              |                |                |
              v                v                |
     发送给 AI API     executeToolCall()    存在性检查
                       返回 { status,
                         componentType,
                         props }
```

### 渲染管线

```
tool-call-card.js
    |
    ├─ 工具名 → TOOL_COMPONENT_MAP → componentName
    |   例: plot_function → function-plot
    |
    └─ renderMathResult(container, componentName, props)
         |
         └─ renderMathComponent()
              |
              ├─ 已加载 → 同步渲染
              └─ 未加载 → 显示骨架屏 → 异步 import()
                   |
                   └─ 加载成功 → replaceChild 替换骨架屏
                        加载失败 → 显示错误提示
```
