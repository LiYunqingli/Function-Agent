# Function-Agent 生命周期文档

本文档描述应用中各层级对象的生命周期，包括应用启动、请求处理、工具调用、组件渲染和全屏交互的完整流程。

---

## 1. 应用启动生命周期

### 1.1 启动序列

```
浏览器加载 index.html
    |
    ├─ 加载 CDN 依赖（KaTeX、Plotly、math.js、marked、highlight.js）
    ├─ 加载 10 个 CSS 文件（variables → base → layout → ... → modal）
    ├─ 执行 <script type="module" src="js/app.js">
    │
    └─ app.js 启动流程
         |
         ├─ ① registerAllTools()          // 注册 24 个工具到 registry
         │      └─ definitions/*.js executor + schemas.js schema → registry.register()
         │
         ├─ ② applyTheme(settingsStore.getState().theme)
         │      └─ 读取存储的主题设置，设置 data-theme 属性
         │
         ├─ ③ 监听系统主题变化
         │      └─ matchMedia('(prefers-color-scheme: dark)')
         │
         ├─ ④ 初始化 UI 组件
         │      ├─ initSidebar(chatStore)       // 会话列表
         │      ├─ initTopBar(settingsStore)    // 顶栏按钮
         │      ├─ initMessageList(chatStore, toolStore) // 消息渲染
         │      ├─ initInputBar()                // 输入栏（返回 API）
         │      ├─ initChatArea(chatStore, settingsStore, toolStore, inputBarApi)
         │      └─ initSettingsDialog(settingsStore) // 设置弹窗
         │
         ├─ ⑤ 欢迎页面逻辑
         │      ├─ updateWelcomeVisibility()  // 检查是否有活动会话
         │      └─ 订阅 activeSessionId/sessions 变化
         │
         └─ ⑥ 启动完成
                └─ console.log('Function-Agent v1.0 已启动')
```

### 1.2 Store 初始化

每个 Store 单例在首次 import 时自动执行构造函数：

**ChatStore**
```
constructor()
    ├─ 初始状态: { sessions: [], activeSessionId: null, isStreaming: false, abortController: null }
    ├─ loadFromStorage()  // 从 localStorage 读取会话数据
    │      ├─ 读取 gaoshu_sessions → 限制 MAX_SESSIONS(100)
    │      └─ 读取 gaoshu_active_session_id
    └─ 订阅全局变更 → 防抖 500ms 自动 saveToStorage()
```

**SettingsStore**
```
constructor()
    ├─ 初始状态: DEFAULT_SETTINGS 合并 localStorage 中存储的设置
    └─ subscribeAll() → 实时保存到 localStorage
```

**ToolStore**
```
constructor()
    └─ 初始状态: { executingTools: {} }
    // 不持久化，每次刷新重置
```

## 2. 请求处理生命周期

### 2.1 handleSend — 发送消息

```
handleSend()
    |
    ├─ _sendLock 检查 → 已锁定则拒绝
    ├─ 检查输入（文本/图片）→ 为空则拒绝
    ├─ _sendLock = true ← 加锁
    |
    ├─ 确保活动会话 → 无则 createSession()
    |
    ├─ 图片处理（如有图片）
    │      ├─ fileToBase64() 编码所有图片
    │      ├─ 添加用户消息（含 images base64）
    │      ├─ 创建 _isVisionThinking 占位消息
    │      ├─ analyzeImages() → 调用多模态 API
    │      ├─ 合并图片描述 + 用户文本 → combinedUserContent
    │      └─ 更新占位消息为正常流式消息
    |
    ├─ 无图片
    │      └─ 创建普通助手占位消息（isStreaming: true）
    |
    ├─ 清空输入栏
    ├─ runAI(sessionId, msgId, userContent, userMsgId)
    |
    └─ finally: _sendLock = false ← 解锁
```

### 2.2 runAI — Agent Loop

```
runAI(sessionId, assistantMsgId, userContent, userMsgId)
    |
    ├─ _runAIGeneration++ → 获取代际 ID
    ├─ _activeStreams++
    ├─ isStreaming = true, 创建 AbortController
    |
    └─ while(true)
         |
         ├─ 深度检查: depth > MAX_TOOL_DEPTH(25) → 中断
         ├─ abort 检查: signal.aborted → 中断
         |
         ├─ buildMessages()
         │      ├─ 过滤占位消息、错误消息、thinking 消息
         │      ├─ stripThinkContent() 剥离 <think...> 标签
         │      ├─ 工具结果转自然语言描述
         │      └─ compactMessages() 角色交替合规化
         |
         ├─ createStream(messages, schemas, settings, callbacks, signal)
         │      ├─ 发送 SSE 请求到 API
         │      ├─ onContentDelta → 实时更新消息内容
         │      └─ 返回 { toolCalls, emptyResponse }
         |
         ├─ 空响应处理 → 生成 fallback 回复或提示错误 → break
         |
         ├─ 无 toolCalls → 确保内容清理 → _autoTitle() → break
         |
         └─ 有 toolCalls
              ├─ 更新当前助手消息（保留文本 + 记录 toolCalls）
              ├─ 逐个执行工具
              │      ├─ toolStore.startExecution(id, name)
              │      ├─ executeToolCall(tc)
              │      │      ├─ registry.getExecutor(name)
              │      │      ├─ executor(args) → result
              │      │      └─ toolStore.completeExecution / failExecution
              │      └─ 添加 tool 消息到会话
              ├─ 创建新的助手占位消息
              ├─ depth++
              └─ 继续下一轮 while

    finally:
         ├─ _activeStreams--
         └─ _safeResetState(myGeneration)
              └─ 代际匹配 → isStreaming = false
```

### 2.3 createStream — SSE 请求

```
createStream(messages, tools, settings, callbacks, signal)
    |
    ├─ normalizeContent() 规范化消息内容
    ├─ 构建 POST /chat/completions 请求体
    │      ├─ stream: true
    │      ├─ tools + tool_choice: 'auto'
    │      └─ temperature / max_tokens
    |
    ├─ fetch() 发送请求
    |
    ├─ 读取 SSE 流
    │      ├─ reader.read() 循环
    │      ├─ 按 \r?\n 分行
    │      ├─ 解析 "data: {...}" JSON
    │      ├─ StreamParser.processChunk()
    │      │      ├─ 文本增量 → onContentDelta
    │      │      └─ 工具调用 → 累积参数块
    │      └─ "data: [DONE]" → 结束
    |
    ├─ 空/中止检测
    │      ├─ finishReason=null + 无 toolCalls → emptyResponse: true
    │      └─ AbortError → toolCalls: null
    |
    └─ 返回 { toolCalls: Array|null, emptyResponse: boolean }
```

## 3. 工具调用生命周期

### 3.1 执行流程

```
executeToolCall(toolCall)
    |
    ├─ toolCall.function.name → 查找 registry
    ├─ 不存在 → 返回 { status: 'error', error: '未知工具' }
    |
    ├─ JSON.parse(toolCall.function.arguments)
    ├─ 解析失败 → 返回 { status: 'error', error: '参数解析失败' }
    |
    ├─ registry.getExecutor(name)
    ├─ executor(args) → await
    │      ├─ 成功 → { status: 'success', componentType, props }
    │      └─ 异常 → { status: 'error', error: message }
    |
    └─ 返回结果
```

### 3.2 工具状态转换

```
[不存在] → startExecution() → [executing]
                               |
                   ┌───────────┴───────────┐
            completeExecution()       failExecution()
                   |                       |
              [success]              [error]
                   |                       |
               渲染组件              显示错误信息
```

ToolStore 状态用于卡片上显示执行状态徽章（排队中/执行中/已完成/失败）和加载骨架屏。

## 4. 组件渲染生命周期

### 4.1 消息渲染

```
ChatStore.addMessage() / updateMessage()
    |
    └─ subscribe('sessions') 触发
         └─ MessageList.onStateChange()
              |
              ├─ diff 计算（对比新旧消息列表）
              ├─ 新消息 → appendMessageToDOM()
              │      ├─ createMessageWrapper()
              │      ├─ role === 'user' → 用户消息气泡
              │      ├─ role === 'assistant' → AI 消息气泡
              │      │      ├─ createToolCallCard()（对每个 toolCall）
              │      │      └─ renderBubbleContent()（文本/Markdown/LaTeX）
              │      └─ 添加到 DOM → fadeIn 动画
              ├─ 更新消息 → updateMessageInDOM()
              │      ├─ 流式文本 → 直接更新 textContent
              │      ├─ 工具结果更新 → 重新渲染卡片
              │      └─ 状态更新 → 更新徽章
              └─ 删除消息 → removeFromDOM() + fadeOut
```

### 4.2 工具调用卡片生命周期

```
createToolCallCard(toolCall, toolResult, toolStore)
    |
    ├─ 创建卡片 DOM（header + body + paramsSection）
    ├─ 状态初始化
    │      ├─ 无结果 → 加载骨架屏 / 执行状态
    │      ├─ 成功 → 显示全屏按钮 + 绑定事件 + renderMathResult()
    │      └─ 失败 → 错误信息
    |
    ├─ renderMathResult(container, componentName, props)
    │      └─ 动态 import('./math/index.js').renderMathComponent()
    │           └─ 动态 import(`./${componentName}.js`)
    │                └─ 渲染器函数(container, props) → HTMLElement
    |
    ├─ 绑定交互事件
    │      ├─ 全屏按钮 click → toggleFullscreen()
    │      ├─ 双击卡片 → toggleFullscreen()
    │      ├─ header click → 折叠/展开 body
    │      └─ body click → 焦点系统
    |
    └─ 返回卡片元素
```

### 4.3 Plotly 图表生命周期

```
Plotly.newPlot(container, data, layout, config)
    |
    ├─ 初始渲染（根据 props 生成 data + layout）
    ├─ 窗口 resize → Plotly.Plots.resize()
    ├─ 全屏切换 → resizePlotlyInElement()
    │      └─ 420ms setTimeout 等待过渡完成后 resize
    └─ 组件销毁 → Plotly.purge(container)（部分渲染器实现）
```

### 4.4 Canvas 动画生命周期

```
创建 canvas 元素
    |
    ├─ 设置尺寸（width/height 属性，非 CSS）
    ├─ 设置 scale（基于容器尺寸自适应）
    ├─ 启动 requestAnimationFrame 循环
    │      ├─ 清屏 → 绘制网格/坐标轴 → 绘制数学元素
    │      └─ 更新动画进度
    |
    ├─ 全屏切换
    │      └─ ResizeObserver 监听容器尺寸变化 → 重新设置 canvas 尺寸
    └─ 动画完成 / 组件销毁
         └─ cancelAnimationFrame()
```

## 5. 全屏交互生命周期

### 5.1 进入全屏（FLIP 动画）

```
toggleFullscreen(card)
    └─ enterFullscreen(card)
         |
         ├─ 单例检查：_activeFullscreen → 先退出旧卡片
         ├─ _activeFullscreen = card
         |
         ├─ FLIP: First
         │      └─ card.getBoundingClientRect() → 保存原始位置和尺寸
         |
         ├─ 创建占位元素（防止布局塌陷）
         ├─ 保存原始样式到 card._fsRestore
         |
         ├─ FLIP: Invert
         │      ├─ card 移到 document.body 下
         │      ├─ position: fixed，设置原始位置尺寸
         │      ├─ zIndex: 9999，margin: 0
         │      └─ transition: none
         |
         ├─ 创建 backdrop（半透明遮罩）
         ├─ 创建关闭按钮
         ├─ 注册 ESC 监听
         ├─ body overflow: hidden
         |
         ├─ FLIP: Play
         │      ├─ 强制 reflow（card.offsetHeight）
         │      ├─ 启用 transition（top/left/width/height）
         │      ├─ 添加 fullscreen 类
         │      └─ rAF → 设置目标位置（0,0,100vw,100vh）+ backdrop active
         |
         └─ setTimeout(420ms) → resizePlotlyInElement()
```

### 5.2 退出全屏（反向 FLIP）

```
toggleFullscreen(card) / ESC / backdrop click / 关闭按钮
    └─ exitFullscreen(card)
         |
         ├─ 获取 placeholder 位置 → targetRect
         ├─ 立即移除 backdrop + closeBtn（不 fade-out）
         ├─ 恢复 body overflow
         ├─ 移除 ESC 监听
         |
         ├─ 设置 transition（仅 top/left/width/height）
         ├─ 设置目标位置/尺寸（= targetRect）
         ├─ ★ 不移除 fullscreen 类（保持 position:fixed）
         |
         ├─ 等待 transitionend（propertyName 过滤）
         |
         └─ snapBack()（原子化操作）
              ├─ transition: none, animationPlayState: paused
              ├─ insertBefore(card, placeholder)（仍 fixed，视觉无变化）
              ├─ placeholder.remove()
              ├─ 移除 fullscreen 类 + 恢复原始内联样式
              ├─ 强制 reflow（void card.offsetHeight）
              ├─ 恢复 transition（用于 hover/focus）
              ├─ cleanupFullscreen()
              ├─ resizePlotlyInElement()
              └─ _activeFullscreen = null
```

### 5.3 焦点系统

```
默认状态：卡片 .tool-call-card（无 .focused）
    └─ 图表容器 pointer-events: none → 滚轮穿透到页面

点击 body → 添加 .focused
    └─ 图表容器 pointer-events: auto → 图表可交互

mouseleave → 移除 .focused
    └─ 恢复 pointer-events: none
```

## 6. 主题切换生命周期

```
用户点击主题切换按钮
    |
    ├─ settingsStore.getState().theme
    |      └─ 三个选项: 'light' | 'dark' | 'system'
    |
    ├─ 循环切换: light → dark → system → light
    |
    ├─ settingsStore 更新 → 持久化到 localStorage
    |
    └─ applyTheme(theme)
         ├─ theme === 'dark' → data-theme="dark"
         ├─ theme === 'light' → 移除 data-theme
         └─ theme === 'system'
              ├─ matchMedia 检测
              └─ 暗色 → data-theme="dark" : 移除

CSS 变量切换
    └─ [data-theme="dark"] 选择器覆盖 :root 变量
         └─ 所有引用 var(--color-*) 的元素自动响应
```

## 7. 数据持久化生命周期

### 7.1 会话数据

```
ChatStore 构造函数
    └─ loadFromStorage()
         ├─ storageAdapter.get('gaoshu_sessions') → Session[]
         └─ storageAdapter.get('gaoshu_active_session_id') → string

任何状态变更
    └─ subscribeAll() 触发
         └─ debounce(500ms)
              └─ saveToStorage()
                   ├─ storageAdapter.set('gaoshu_sessions', sessions)
                   └─ storageAdapter.set('gaoshu_active_session_id', id)
```

### 7.2 容量保护

```
storage-adapter.js
    └─ set(key, value)
         ├─ JSON.stringify(value) → 检测大小
         ├─ 超出 80% 容量 → 按时间清理旧会话
         └─ 超出 100% 容量 → 报错提示用户
```
